# LaunchPad v2.1.12

## Evidence-driven review agents and lint parity

LaunchPad v2.1.12 adds three specialized review agents and makes the review workflow more explicit about evidence, stack compatibility, and incomplete verification. It also aligns the two documented Ruff invocations so local contributors and CI receive the same result.

## Added

- **`lp-claims-auditor`** verifies factual repository claims in commit messages, PR bodies, source-code documentation comments, test names and test comments, README files, and reports. Executable checks require an enforced sandbox; unavailable execution is recorded as a coverage limitation.
- **`lp-foad-go-reviewer`** probes Go parsing, numeric boundaries, aliasing, floating-point behavior, determinism, text handling, resources, staleness, concurrency, and test strength. Probes run only in an isolated, network-denied process sandbox.
- **`lp-document-truth`** reads recipient-facing pages, reports, PDFs, emails, dashboards, and generated documents for false counts, population errors, missing provenance, contradictions, and misleading advisories or refusals.
- **Conditional document review configuration.** Projects opt in through `review_document_agents` and define the exact artifact population with repository-relative `review_document_artifacts` globs.

## Improved

- **Go-aware review dispatch.** `stack:go` matches both `go` and `go_cli` projects and is excluded from unrelated stacks.
- **Deterministic roster handling.** Built-in and project-local reviewers are resolved before dispatch, project-local `stack_scope` values are enforced, unresolved rosters fail visibly, and headless failures persist a P1 todo and failed review summary.
- **Claims context.** Claims auditing receives the exact merge-base-derived commit range, working-tree identity for local fallback modes, PR body, and linked-issue context.
- **Coverage reporting.** Verification blocked by missing tools or a safe execution environment is persisted separately from findings and never presented as a clean, fully verified review.

## Fixed

- **Ruff invocation parity.** Explicit first-party package classification makes the repository-root CI invocation and package-directory contributor invocation agree.
- **Review severity serialization.** Agent-level P0 findings retain their reported source severity and normalize to the existing P1/P2/P3 pipeline schema.

## Upgrading from v2.1.11

No migration is required. Existing `.launchpad/agents.yml` files remain valid. To enable document truth review, add `lp-document-truth` under `review_document_agents` and list the intended output files under `review_document_artifacts`.

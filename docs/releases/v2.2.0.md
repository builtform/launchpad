# LaunchPad v2.2.0

## Codex support and a marketplace that follows releases

LaunchPad v2.2.0 makes LaunchPad installable on Codex through the same BuiltForm marketplace that Claude Code uses. Both hosts read the same command, agent, and skill files, so nothing changes for Claude Code users and nothing is duplicated. This release also changes how releases reach marketplace users: a verified release tag now moves a `stable` branch forward, and the marketplace follows that branch.

## Added

- **Codex adapter.** One router skill, `$launchpad:lp <command>`, resolves and follows the canonical LaunchPad files in place. `/lp-review` on Claude Code is `$launchpad:lp review` on Codex, and `$launchpad:lp help` lists every command from the installed files. Verified on a real Codex `0.154.0-alpha.6.2` installation from the command line: `help`, `hydrate`, and `review` end to end, `harden-plan` to its confirmation prompt, and `commit` to its first prerequisite check. Every other command runs through the same router and is not yet verified on Codex. Installation, the verified list, and the differences from Claude Code are in [How It Works: Codex](../guides/HOW_IT_WORKS.md#codex).
- **Verified release promotion (BL-396).** After the tag checks pass, the release workflow fast-forwards the `stable` branch to the verified tag commit. The branch never moves backward and needs no cross-repository credential.

## Improved

- **Project agents and skills on Codex.** Files in a project's `.claude/agents/` and `.claude/skills/` work from the same paths on both hosts. Stray, malformed, or symlinked entries are skipped and reported instead of blocking built-in items.
- **Dependency updates,** including `anyio` 4.14.2, which resolves two published advisories (GHSA-5p39-cfhj-2xmp and GHSA-82r6-8w77-94w6) in the plugin's script tooling.

## Fixed

- **Project extension failures are isolated.** An unusable project extension entry no longer blocks unrelated built-in commands, agents, or skills on Codex.

## Marketplace users

Installs from the BuiltForm marketplace were pinned to v2.1.3 until now. Starting with this release the marketplace follows `stable`, so an update brings you to the current release. On Claude Code, update with `/plugin marketplace update builtform`, then uninstall and reinstall `launchpad@builtform` as described in [How It Works](../guides/HOW_IT_WORKS.md#updating). On Codex, run `codex plugin marketplace upgrade builtform`, then `codex plugin add launchpad@builtform`.

## Known limits on Codex

Sub-agent tool restrictions are advisory, Claude Code project hooks do not run, and only the command line was verified. The full list, with the date it was last checked, is in [How It Works: Codex](../guides/HOW_IT_WORKS.md#codex). Follow-ups are tracked as BL-386 to BL-397.

## Release validation

- Python suite: 2116 passed, 4 skipped on the release branch.
- TypeScript tests, typecheck, lint, Pyright, Ruff, Prettier, repository structure, plugin validation, freshness checks, and pre-commit hooks pass.
- The Codex install and live help checks pass against `chore/v2.2.0-codex-adapter`.

## Upgrading from v2.1.12

No project migration is required. Marketplace users should follow the update steps above so their installation begins following the `stable` branch.

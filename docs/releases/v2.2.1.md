# LaunchPad v2.2.1

## Cleanup after the Codex release

LaunchPad v2.2.1 is a small cleanup release. Two commands now resolve by their short names in Claude Code, a command that was decommissioned in v2.1 is finally gone from the menus, and the release workflow gains one more safety check. Nothing changes in how you run LaunchPad on either host.

## Fixed

- **Short names resolve for two more commands.** `/lp-pnf` and `/lp-research-codebase` had no `name` field, so Claude Code answered "Unknown command" to the short form and accepted only `/launchpad:lp-pnf` and `/launchpad:lp-research-codebase`. Both now carry the field. `/lp-research-codebase` also gains a description.

## Removed

- **`/lp-pull-launchpad`.** The command was decommissioned in v2.1 and survived only as a stub that still appeared in command menus on both hosts. The stub and its mentions in the guides are removed. LaunchPad now has 42 commands. To update the plugin, follow [How It Works: Updating](../guides/HOW_IT_WORKS.md#updating).

## Improved

- **Codex desktop app checked (BL-391).** LaunchPad installed through the BuiltForm marketplace loads and runs in the Codex desktop app, which shares its plugin configuration with the command line. The IDE extension remains unsupported because it does not load plugins.
- **Release notes are required for promotion (BL-397).** The release workflow refuses to move the `stable` branch when `docs/releases/<tag>.md` is missing. The documented recovery for a failed verification now reruns the failed jobs of the original tag-push run, which is the only path that promotes a release.
- **Three `mcp` advisory suppressions removed.** The dependency now resolves to a version that contains the fixes, so the vulnerability scan runs with no active suppressions.

## Release validation

- Python suite, TypeScript tests, typecheck, lint, Pyright, Ruff, Prettier, repository structure, plugin validation, freshness checks, and pre-commit hooks pass on the release branch.
- Claude Code loads 42 commands, 16 skills, and 39 agents from the release branch, and the short forms `/lp-pnf` and `/lp-research-codebase` resolve.

## Upgrading from v2.2.0

No project migration is required. Marketplace installs follow the `stable` branch and receive this release on their next update.

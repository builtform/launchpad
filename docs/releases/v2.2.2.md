# LaunchPad v2.2.2

## Greenfield pipeline and database review fixes

LaunchPad v2.2.2 fixes eight defects found when running the full pipeline on a new project. A new project now goes from brainstorm to bootstrap without clearing LaunchPad's own folders, chooses its stack from an honest shortlist, and gets bootstrap files that match that stack. Database review now covers every migration tool LaunchPad scaffolds, plus Drizzle and Prisma.

## Fixed

- **Brainstorm and retry without clearing LaunchPad's own folders.** `docs/brainstorms/`, `.harness/` run logs and Finder or Explorer noise files no longer make the greenfield pipeline treat a new project as an existing one. A real manifest still marks a project as brownfield.
- **An honest stack shortlist.** Undecided answers keep eligible categories in the shortlist. `/lp-pick-stack` proposes answers from the brainstorm for your confirmation, explains how the candidates fit its constraints, and seals your choice, including ties across categories.
- **Database review across migration tools.** `/lp-review` detects Prisma, Drizzle, Supabase, Rails, Alembic, Django and plain SQL changes and gives the database reviewers context for the tool in use. Detection reads project files as text and never runs project config.
  - Data-only migrations are no longer reported as schema drift, and resolved migration merges no longer count as divergent branches.
  - The integrity review flags an exposed Supabase table without row level security as P1. A table with row level security and no policy gets a P3 note asking you to confirm it is service-only.
  - `/lp-ship` adds every detected schema, migration and database path to its no-auto-fix list in each round, and falls back to its built-in list if detection fails.
- **Repository URL updates with personal data opted out.** `/lp-update-identity` can fill the repository URL while keeping personal-data placeholders, and its preview validates with the same checks as the write.
- **The structure check passes on a new project.** It accepts generated files, declared layer roots and the agent names LaunchPad ships.
- **Bootstrap files match the selected stack.** Hooks, ignore files and the structure check use one normalized stack source, including the sealed stack decision before the project config exists.
- **Declared frontends get the UI pipeline.** A declared frontend keeps the design stages, browser tests and an app-flow skeleton, and empty gate commands are filled with editable defaults when the toolchain allows.

## Improved

- **Stack knowledge brought up to date.** The knowledge anchors that guide scaffolding were re-checked against upstream and now cover Expo SDK 58, FastAPI 0.162, Supabase CLI v3, Next 16.4, Astro's Node 22.23.4 floor, Django 6.1.3, Rails 8.1.4.1, Hono 4.13 and Hugo 0.169. Generated docs for new Expo projects name SDK 58.
- **Catalog and contract documents corrected.** The stack catalog no longer lists `--reset-preferences` for `create-next-app`, which makes it exit without scaffolding, and it now lists the `--install` flag `create-hono` needs to run without a prompt. `SCAFFOLD_HANDSHAKE.md`, `SCAFFOLD_OPERATIONS.md` and the pillar framework were re-read against the code and corrected where they had drifted. The rollback procedure, for example, now ships a fixed patch, because `stable` only moves forward.

## Known gaps

The database detector does not yet recognize these layouts. A later release will cover them.

- SQLAlchemy models declared only with `Mapped[...]` annotations.
- Flask-SQLAlchemy models declared with `db.Model` and `db.Column`.
- Django model modules nested deeper than `models/*.py`.
- `alembic.ini` outside the repository root.
- Changes that delete a Django app or Alembic anchor file.
- A root `prisma.config.*` that configures a Prisma project in a subfolder.
- Custom Prisma schema and migration locations set in `prisma.config.*`.
- Drizzle config paths that reach a sibling folder in the repository through `..`.

## Release validation

- Python suite (2407 passed, 5 skipped), TypeScript tests, typecheck, lint, Pyright, Ruff, Prettier, repository structure, plugin validation, the handshake lint, the release freshness gate (all 16 targets within 30 days) and pre-commit hooks pass on the release branch.
- Claude Code loads 42 commands, 16 skills and 39 agents from the release branch, the same as v2.2.1.

## Upgrading from v2.2.1

Marketplace installs follow the `stable` branch and receive this release on their next update.

Projects bootstrapped by an earlier version: run `/lp-bootstrap --accept-plugin-version-drift` once to re-render the hooks, ignore files and structure check. User edits are backed up under `.launchpad/backups/`. If an earlier version wrote a brainstorm summary while the folder was classified as ambiguous, run `/lp-brainstorm` once to refresh it before choosing a stack.

# LaunchPad v2.1.11

## v2.1.11 ship: every scaffolder recipe re-validated, CVE-watch lane repaired, dependency sweep

**v2.1.11 fixes scaffolding.** Hono scaffolds could not run at all; Astro scaffolds installed dependencies and committed a nested git repository behind LaunchPad's back; Next, Astro and Expo scaffolds overwrote the harness-authored `CLAUDE.md`; Rails scaffolds shipped with no JavaScript entrypoint. Anyone running `/lp-build` against those stacks is affected. The specifics are in [For LaunchPad users](#for-launchpad-users-downstream-behavior-changes) below.

Those defects surfaced because the 30-day freshness window on LaunchPad's scaffolder knowledge anchors lapsed while this release was being cut. Rather than re-stamp 16 dates, every target was re-verified against live upstream sources. **Zero of eleven anchors were accurate**, and the executable catalog (`scaffolders.yml`) had drifted further still. A weekly early-warning workflow now files an issue before the window lapses, rather than surfacing the problem as a blocked release.

The release also closes out the post-v2.1.10 Dependabot backlog (32 bumps, unblocked by the v2.1.10 freshness-gate fix) and repairs three CI failures that were firing on a schedule with nobody acting on them: the `cve-watch` workflow had been broken since `osv-scanner` v2 removed a flag it passed, the same workflow's tag-drift detector was reporting false positives, and a `ruff` minor bump silently expanded the default rule set under a config that could not pin it.

## Highlights

- **All 16 freshness targets re-validated against live upstream (#145).** The OPERATIONS §4 window lapsed at 39 days. Every target was re-verified against npm, PyPI and RubyGems registries, GitHub release APIs, official docs, and in several cases the scaffolder's own source tree. Zero of eleven knowledge anchors were accurate. Three failure classes surfaced, and only the first is what a time-based window can catch:
  1. **Version drift (11 of 11).** `create-next-app` 15 to 16, `astro` 5 to 7, Django 5.1 (EOL) to 6.0, Rails 8 to 8.1, FastAPI 0.115 to 0.141, Expo SDK 52 to 57, Hugo 0.137 to 0.164, `supabase-js` 2.45 to 2.111.
  2. **Detection signals keyed on removed paths.** These fail _silently_: the harness misidentifies a stack in a brownfield repo and nothing errors. Next `middleware.ts` to `proxy.ts`; Astro `src/content/config.ts` to `src/content.config.ts`; Hono `wrangler.toml` to `wrangler.jsonc`; Expo `babel.config.js` no longer generated at all; Supabase `supabase/schemas/` missing entirely.
  3. **Claims that were never true.** No re-stamp cadence catches these, because they never drifted. The Eleventy anchor stated "Eleventy 3 is ESM-only; CommonJS removed" and carried a pitfall instructing a rename to `.mjs`; both are false, since v3 added ESM while explicitly keeping CommonJS. That is the one finding that would have made the harness break a working repo rather than merely misconfigure a new one. Also: a Hono `await next()` migration pitfall absent from upstream's `MIGRATION.md`, and Supabase `SUPABASE_INIT_*` environment variables that exist in no official source.

  Two anchors had been stamped `2026-06-23` while already contradicting upstream events from 2026-06-19 and 2026-06-22, which is direct evidence the prior re-stamp was a date bump rather than a check.

- **Executable catalog corrected to match (#145).** The larger defect. The anchors are documentation; `scaffolders.yml` is what actually runs, and the two had diverged. See [For LaunchPad users](#for-launchpad-users-downstream-behavior-changes) for the per-stack impact.
- **Weekly anchor-freshness early warning (#144).** `anchor-freshness-watch.yml` runs `plugin-freshness-check.py` on a schedule and opens (or updates) a GitHub issue once any target enters a configurable lead window before its 30-day deadline, so staleness is caught while it is cheap instead of at tag time. The workflow is split into two jobs: the checking job runs with `contents: read` only, and the issue-filing job holds `issues: write`, skips `pull_request` events, and never checks out the PR's code. Its verdict discriminator requires the script's stdout and exit code to agree, and errors out loudly on any incoherent combination rather than defaulting to "fresh".
- **CVE-watch workflow restored (#123, #124).** `osv-scanner` v2 removed the `--skip-git` flag (skipping the git root is now the default), so every scheduled run of `cve-watch.yml` failed at invocation before scanning anything. The flag was dropped and the companion tag-drift detector was corrected. The workflow also gained a `pull_request.paths` guard so it runs on PRs that actually touch the scanner config, the requirements lockfile, or the workflow itself, instead of on every PR.
- **`mcp` transitive CVEs suppressed with an expiry (#138).** `semgrep` hard-pins `mcp==1.23.3` (an exact pin, still true at 1.171.0), which blocks the fixed versions for three advisories. They are suppressed in `osv-scanner.toml` with `ignoreUntil = 2026-10-31` and a written reason, so the suppression expires and re-surfaces rather than becoming permanent. The stale `click` suppression from the previous pin generation was deleted; `semgrep` 1.171.0 moved `click` to 8.4.2 on its own.
- **`ruff` configuration pinned to an explicit rule set (#138).** The config used `extend-select`, which layers on top of whatever `ruff` currently considers default. `ruff` 0.16.0 expanded that default set, so a routine minor bump surfaced 138 new findings across the Python tree. All 138 were triaged individually (not deferred to a backlog item): the ones worth enforcing were adopted as explicit rule codes under `select`, and each rule deliberately left out carries an inline rationale. The config also gained `force-exclude = true` so explicit-path invocations honor the exclude list.
- **`_vendor/*_VERSION` pin files deleted for tools that no code reads (#138).** Five files (`RUFF`, `PYRIGHT`, `BANDIT`, `SEMGREP`, `PYTEST`) documented versions that nothing consumed, and `requirements.in` instructed maintainers to sync `requirements.txt` _from_ them. `RUFF_VERSION` still read `0.11.12` against a `requirements.txt` pin of `0.16.0`, so anyone following the instruction silently downgraded their linter by five minor versions. The four pin files that are actually read at runtime (`JINJA2`, `MARKUPSAFE`, `PSUTIL`, `PYYAML`) are retained, and the `requirements.in` note now names `requirements.txt` as authoritative.
- **`vitest` 1.x to 4.x with the first API tests (#120, #122).** `vitest` 1.6.1 was three majors behind and the root workspace config was dead (`vitest` 3 activates projects through `test.projects`). The migration went 1.6.1 to 3.2.6 to 4.1.10. `vitest` 4 moves `vite` from a direct dependency to a peer dependency, so `vite` is now an explicit root dev dependency. The `apps/api` bootstrap was split into `app.ts` (the app factory) and `index.ts` (the server entry) so the app is testable without binding a port, and the first `/health` test landed alongside it.

## Fixed

- **Every Hono scaffold failed at argument parsing (#145).** `scaffolders.yml` passed `--yes`, an option `create-hono` does not define; commander rejects unknown options. Non-interactivity now comes from the target positional plus `--template`, with `--pm npm` pinning the package manager so no prompt can appear.
- **Astro scaffolds installed dependencies and created a nested git repository (#145).** `create-astro` resolves install as `ctx.install ?? ctx.yes` and git as `ctx.git ?? ctx.yes`, so a bare `--yes` silently ran `npm install` and `git init/add/commit` inside the scaffold step, both of which LaunchPad owns. Now passes `--no-install --no-git`, plus `--no-ai` to suppress an `AGENTS.md` and a `CLAUDE.md` symlink.
- **Next, Astro and Expo scaffolds overwrote the harness-authored `CLAUDE.md` (#145).** All three upstream CLIs began emitting agent instruction files by default (`--no-agents-md` on Next 16.2 and Expo SDK 56; `--no-ai` on Astro). Expo SDK 56 also writes `.claude/settings.json`. All three flags are now passed. Next additionally gained `--reset-preferences`, because `--yes` reuses previously saved CLI preferences and so produced non-reproducible output on any machine that had run `create-next-app` before; the redundant `--turbopack` was dropped, Turbopack being the Next 16 default.
- **Rails scaffolds shipped with no JavaScript entrypoint (#145).** `--skip-bundle` does not merely defer `bundle install`: `run_solid`, `run_hotwire`, `run_javascript`, `run_css` and `run_kamal` all early-return on `!bundle_install?`. Scaffolds were produced with no `config/importmap.rb`, `bin/importmap` or `app/javascript/**`, and no Solid Queue/Cache/Cable config, and a later `bundle install` does not create any of them. The flag was removed rather than deferred to a backlog item, letting the generator own its own install (the same call the Expo entry in this catalog already makes). BL-381 tracks the cleaner fix: a per-stack post-install hook that would let `--skip-bundle` return.
- **Adapter and template layers reconciled with what each actually materializes (#145).** `astro.py` stays on Astro 6, deliberately _not_ the anchor's 7, because it renders templates pinned at `withastro/astro@astro@6.2.2` rather than invoking the upstream CLI; the anchor and the adapter describe different code paths and each must track its own output. `ts_monorepo` dropped its hardcoded Next major entirely, since its `describe_*` functions also run for brownfield repositories where any fixed value is wrong. New `test_adapter_version_agreement.py` asserts an adapter module and its own template fragments cannot disagree about a framework version; it is mutation-verified in both directions and caught two defects in #145's own commits within minutes of being added.
- **`osv-scanner` v2 flag removal broke every scheduled CVE scan (#123).** `--skip-git` was removed in v2; passing it is a hard invocation error.
- **Tag-drift detector false positives (#124).** The detector compared refs in a way that reported drift on tags that were correctly placed.
- **`v2-handshake-lint` freshness check read the local clock (#138).** The freshness comparison used the runner's local date while `plugin-freshness-check.py` used UTC, so the two gates could disagree by a day depending on timezone. Three call sites now route through a shared `_today_utc()` helper mirroring the canonical checker, and the future-date guard gained a one-day skew tolerance. Seven tests pin the behavior under `Pacific/Kiritimati` (UTC+14) and `Etc/GMT+12`.
- **Test-suite time bomb in the template-cache fixture (#138).** A fixture wrote a hardcoded `fetched_at` timestamp that would have started failing the cache-freshness assertions within days. It now stamps the current UTC time.
- **`/lp-bootstrap --recover` doc and implementation divergence (BL-376, #138).** The documentation described a manifest-unlink step on recovery that the engine does not perform. Unlinking would discard a rendered manifest whose absence the policy layer treats as first-bootstrap (`action=WRITE`), so the documented behavior was the wrong one: the docs were corrected and the unlink withdrawn rather than built. `BootstrapResult` gained a `status` discriminator so a sentinel-clear-only recovery is distinguishable from a full recovery, and the unused `STALE_SENTINEL_DETECTED` / `STALE_SENTINEL_THRESHOLD_HOURS` constants were removed. Five tests pin the semantics, including the deliberate non-unlink.
- **Backlog-orphan gate hard-failed on a closed BL (#139).** BL-376's status line read `RESOLVED`, which is not one of the keywords `plugin-backlog-orphan-check.py` recognizes (`shipped`, `closed`, `re-targeted`, `deferred`, `superseded`). Because BL-376 is labeled for v2.1.11, the gate flagged it as an orphan the moment this release was tested (`--release 2.1.11` FAIL, `--release 2.1.10` PASS). Corrected to `SHIPPED`, with an inline note naming the recognized keyword set.

## Documentation

- **BL-377 filed (v2.2, P3).** `plugin-backlog-orphan-check.py` matches `^\*\*Status[^*]*\*\*:` at line start, so it cannot read the bullet-form `- **Status**: TODO` used by BL-100..BL-105, BL-200..BL-202, and the Standard Task Format itself. Not implemented in this release.
- **BL-378 filed and its remedy corrected (v2.2, P2, #138, #139).** The schema-CODEOWNERS gate passes whenever `SCAFFOLD_HANDSHAKE.md` appears anywhere in the PR diff, without checking that the doc change relates to the schema change, so any bundled formatting pass satisfies it vacuously. The entry originally proposed `git diff --ignore-all-space` as the fix; tested against the real PR #138 diff, that still reports the file as changed, because Prettier 3.9 rewrites markdown table separator rows (`|--------|` becomes `| --- |`) and a change in dash-run length is not a whitespace difference. The remedy was replaced with a table-row-scoped normalizer that collapses separator dash runs and cell padding, leaving code blocks and prose byte-exact. Not implemented in this release.

## For LaunchPad users (downstream behavior changes)

**Scaffolding changes for five stacks.** If you run `/lp-build` (or any command that scaffolds) against Hono, Astro, Next, Expo or Rails, the generated project differs from v2.1.10:

| Stack | Before                                                                                           | After                                                                 |
| ----- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| Hono  | scaffold failed at argument parsing, every time                                                  | works                                                                 |
| Astro | installed `node_modules` and ran `git init/add/commit` mid-scaffold; wrote a `CLAUDE.md` symlink | neither; LaunchPad owns install and git as it always intended         |
| Next  | wrote `AGENTS.md` + `CLAUDE.md` over the harness copy; reused saved CLI preferences              | `--no-agents-md` + `--reset-preferences`, so output is reproducible   |
| Expo  | wrote `AGENTS.md`, `CLAUDE.md` and `.claude/settings.json` over harness files                    | `--no-agents-md`                                                      |
| Rails | no JavaScript entrypoint, no Solid Queue/Cache/Cable config, unfixable by `bundle install`       | full app; `bundle install` now runs inside the scaffold step (BL-381) |

The Rails change means the scaffold step takes longer, because `bundle install` now runs as part of it rather than being skipped. That is the intended trade: a scaffold that finishes fast while producing an unusable app is the worse failure.

**Documentation accuracy.** Eleven scaffolder knowledge anchors were rewritten. If you have read LaunchPad's Eleventy guidance and migrated a working project to `.mjs` on the strength of it, that instruction was wrong: Eleventy 3 kept CommonJS. The Supabase `SUPABASE_INIT_*` environment variables never existed.

**Everything else is LaunchPad-internal.** Downstream projects do not run `cve-watch.yml`, `v2-handshake-lint`, `anchor-freshness-watch.yml`, or the backlog-orphan gate; those are LaunchPad's own workflows. The `/lp-bootstrap --recover` fix (BL-376) corrects documentation to match shipped behavior, so no downstream flow changes. The dependency bumps are build-time or template-scoped.

## Scope deferred from v2.1.11

- **BL-377** (backlog-orphan gate bullet-form `Status` lines): filed, deferred to v2.2. P3.
- **BL-378** (schema-CODEOWNERS gate neutralized by bundled formatting passes): filed with a verified remedy, deferred to v2.2. P2.
- **BL-365 / BL-366 / BL-367 / BL-368** (existing v2.1.x candidates): not in this release; carrying forward.
- **BL-374** (TypeScript 5.x to 6.x) and **BL-375** (Prisma 6.x to 7.x): remain v2.2.
- **BL-379** (P2): two OPERATIONS §4 mechanisms are documented but implemented by nothing, namely the re-stamp affirmation trailer with chain-of-custody and the `verdicts:` / `waivers:` report schema. The missing waiver path matters most: without one, the only thing that satisfies the release gate is editing the dates, which is precisely the pressure toward a dishonest stamp. Filed, deferred.
- **BL-380** (P3): promote the Supabase entry from `curate` back to `orchestrate`. The original demotion rationale ("`supabase init` is mixed-prompts and would hang on stdin") is obsolete, since init is now non-interactive by default. Held anyway, because promotion is a behavior change that needs its own verification pass against a real `supabase init` run, not a same-PR flip justified by reading docs.
- **BL-381** (P2): a per-stack post-install hook, which would let Rails pass `--skip-bundle` again and move the install into the cross-cutting wiring step. Partially addressed here by removing the flag.
- **BL-382** (P3): adapter version metadata should be derived from `pin_registry.py`, not hardcoded in each adapter module.
- **BL-383** (P2): no gate models cross-file claim propagation. One wrong sentence in an anchor reached five layers in this release, and every copy was found by a reviewer rather than by CI. The new adapter-agreement test covers one of those boundaries; the rest remain unguarded.

## Test count

2011 passing + 4 skipped in the Python suite, measured on this release's head (up from 1975 + 4 at v2.1.9). The largest contributions are 12 tests from #138 (five pinning `--recover` semantics, seven pinning the freshness-lint UTC clock under shifted timezones) and 6 from #145 (`test_adapter_version_agreement.py`). The TypeScript suite gained its first tests: `apps/api` now covers the `/health` endpoint against the extracted app factory.
